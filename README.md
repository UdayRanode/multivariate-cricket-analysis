## Objective

Cricket generates massive, highly correlated datasets — 22 players × 15+ stats each means a single match contains **over 330 overlapping variables** (runs, boundaries, balls faced, wickets, catches, etc.).

The goal of this project is to build a predictive model that accurately forecasts a cricket player's fantasy Points *before* the match starts, using a 4-stage Process Data Analytics pipeline:

1. **Data Cleaning & Preparation**
2. **Data Analysis** (dimensionality reduction, feature selection)
3. **Data Interpretation & Visualization**
4. **Data Collection** (feeding back into the model pipeline)

The final deliverable is a mathematically optimized, algorithmically drafted **Dream XI**, selected purely on model-predicted fantasy points.

---

## Dataset

- **Structure:** 1 row = 1 complete cricket match.
- **Dimensionality:** 300+ raw columns per match, growing to 1,600+ after including per-player historical/lifetime statistics.
- **Input features (X):**
  - **Match context:** Format (ODI, Test, T20), venue, match type
  - **Player statistics:** 14+ performance metrics for all 22 players on the field (runs, wickets, 4s, 6s, catches, maidens, balls played, etc.)
  - **Historical form:** club/international, previous-3-match and lifetime stats per player, per format
  - **Weather:** temperature, humidity, dew point
- **Target (Y):** the fantasy points score generated by each player — the value the model is trained to predict *before* the match.
- **Splits:** `train_weather_data.csv` (model training) and `test_waether_data.csv` (blind evaluation).

## Methodology

### 1. Data Preparation & Scaling
- Missing values handled via **median imputation** to avoid skewed outliers affecting baseline metrics.
- **Z-score normalization** applied across all numerical features.
- **Variance thresholding** to drop zero-variance columns.

### 2. Performance Monitoring
- Match data is inherently **chronological/sequential** — past performance informs future predictions.
- Used a **Time-Series Split** for cross-validation (instead of standard K-Fold) to prevent data leakage across time.

### 3. Dimensionality Reduction (PCA)
- PCA scree plot used to select the number of principal components.
- ~26 components capture ~60% of total variance in the raw feature space.
- PCA score plots (PC1 vs PC2) used to visualize match clustering.

### 4. Feature Selection (PLS + VIP)
- A **Projection to Latent Structures (PLS)** model maps player statistics (X) to fantasy points (Y).
- **Variable Importance in Projection (VIP) scores** quantify each feature's contribution.
- Features filtered with a strict threshold of **VIP > 1.0**, isolating "critical-to-quality" variables (recent form, runs, wickets, etc.) and reducing ~1,153 preprocessed features down to 235 VIP-selected features.

### 5. Predictive Modelling
Four models were trained and compared using **5-fold Time-Series Cross-Validation**:

| Model | Input | Notes |
|---|---|---|
| K-Nearest Neighbors (KNN) | 26 PCA components | Best K=10 chosen via CV |
| **Ridge Regression** (MLR + L2) | 235 VIP-selected features | α = 1.0; multi-output, predicts all 22 players simultaneously |
| Artificial Neural Network ("Soft Sensor") | VIP-selected features | 2 hidden layers (128 → 64 neurons), 500 iterations |
| PLS Regression | — | Baseline model |

**Why "Soft Sensor"?** Fantasy points are a delayed measurement — only known after the match ends. The ANN estimates this hard-to-measure output *before* the match using only easy-to-measure, pre-match historical stats, exactly mirroring how a soft sensor works in process engineering.

## Results

| Model | MAE | RMSE | R² |
|---|---|---|---|
| KNN | 28.88 | 38.75 | 0.317 |
| **Ridge Regression** | **8.16** | **12.10** | **0.937** |
| Neural Network | 13.36 | 18.98 | 0.846 |
| PLS (Baseline) | 31.18 | 41.32 | 0.233 |

**Selection criterion:** lowest MAE.

🏆 **Ridge Regression is the best-performing model** — explaining 93.7% of the variance in fantasy points, with an average prediction error of only 8.16 points per player.

## Known Issues

- **Test set column mismatch:** `test_waether_data.csv` currently has 1,601 columns vs. 1,662 in the training file. The header row is truncated near the end, causing the `Temperature`, `Humidity`, and `DewPoint` weather features (and several `team2_player11` historical-stat columns) to be dropped/duplicated. This should be regenerated from source before final evaluation, since the current script silently zero-fills the missing columns via `reindex(..., fill_value=0)` rather than raising an error.
- **High dimensionality vs. sample size:** ~900 training rows against 1,600+ raw features makes the unreduced feature space prone to overfitting; PCA/PLS+VIP filtering mitigates this but should be monitored on new data.
- **Multi-output scale:** with 330 simultaneous player-attribute targets, some of the more expensive models (Gaussian Process, SVR, CatBoost/XGBoost wrapped in `MultiOutputRegressor`) can be very slow to train; the reported comparison above uses the lighter, VIP-filtered pipeline (KNN, Ridge, ANN, PLS).
